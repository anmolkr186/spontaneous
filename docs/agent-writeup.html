Spontaneous

Designing an agent that edits video through typed tools

Spontaneous is a macOS app that turns screen recordings into product videos. You leave notes on the frame by drawing, speaking or typing, and an agent turns each note into timeline edits you can review and undo.

Anmol Kumar, designer and builder. November 2026.

Where it stands

Built
The recorder, editor, timeline, shot library, design system and the full agent interface: thread, tool cards, per-edit undo, questions, stop and queueing.
Scripted
The agent itself. A stand-in plays runs using the same message shapes the real integration will use, and its edits change the real project state. No model is involved yet.

The experience

A note is anchored to a moment and, optionally, a region of the frame. Applying it starts a run in the sidebar, where each tool call appears as its own card. Edits carry an Undo, so you judge the agent's work one change at a time.

  1. NoteInk, voice or text, tied to a time and region
  2. AgentReads the project and the frame, then decides on edits
  3. Typed toolsEach call is validated before it applies
  4. TimelineThe edit appears live and can be undone

Design decisions

  • The agent's only way to act is the tool surface

    The session allows only the app's own tools, with built-in file and shell tools turned off. That keeps its reach easy to explain: it can change this video project and nothing else on your machine.

  • Tools are shaped like the user's vocabulary

    Tools map to things you can see on the timeline, such as a zoom, a cut or a blur. A tool card therefore reads as a plain edit, and the same names work for people, the agent and the undo history.

  • Every write is an undoable command

    Agent edits go through the same command system as manual edits, tagged with who made them. Undo, audit and conflicts between you and the agent then become one model instead of three features.

  • The agent can look and can ask

    render_frame lets it see the actual frame, and ask_user shows a question as choice buttons in the thread. A vague note can get a quick answer instead of a confident wrong edit.

  • Control during a run is designed, not implied

    Notes sent while the agent is busy wait under the thread as Up next. Stop clears the queue and returns unfinished notes to open, while finished edits stay and can still be undone.

What the orchestration will do

The goal is that you connect Claude once from the sidebar and then only think about notes. The app takes care of the rest:

  1. Find Claude Code on your machine and start it with access to the app's tools only.
  2. Turn open notes into runs, and hold the next run while the agent is busy or waiting on your answer.
  3. Stream the agent's output into the thread, showing text, reasoning and tool cards as they arrive.
  4. Show permission requests and questions as choices in the thread, then send your answer back to the agent.
  5. Link each resolved note to the edits that answered it, so those edits can be reverted together.
  6. Clean up agent processes when you stop a run or quit, and remove any left behind on the next launch.

What I still need to learn

A script never misreads a note, so the interface hasn't yet been tested against a real agent's mistakes. Once Claude is connected, I want to see how people review a run that is partly wrong, and whether tool cards give enough detail to trust an edit without replaying the video. I also expect connection and sign-in failures to need their own design, because they are the first thing a new user could hit.
